# 策略系统现状与量化准备度审计

状态：只读审计与建议，尚未实施新策略或交易功能。
问题：系统积累的数据是否足以优化策略，以及能否继续发展为量化交易系统？

## 结论

已有题材主因、板块成分、实时强弱、收盘价、五档L2、预测和事件记录等研究基础。
但目前尚不能证明存在可执行、扣除成本后稳定的交易优势。当前第一优先级是恢复数据连续性，
区分采集故障与策略否定，再保存可按当时可用信息回放的样本。

本轮不计算收益率、夏普或最大回撤：没有为每个信号确定真实可成交时间/价格、仓位、退出与交易成本，
也没有将正常日、故障日及超出留存窗口的日期统一成可靠的评估总体。

## 评估口径中的缺口

1. 预判回看evalStock以信号日收盘价为基础计算次日收盘和3日涨幅；次高为次日最高价相对基础价。
   它是股票后续表现，尚非真实进出场与成本后的收益。次高尤其不能默认全部兑现。
2. 成立率/封板率大多评估已生成的候选或正式方向，没有覆盖全市场漏选机会及失败日的召回问题。
   在市场缺机会和采集故障之间需要显式区分，故障日不应作为正常负样本，也不应从运营可用率中消失。
3. 现有归因过滤、历史词典纪元和重建证据保护有价值，但schemaVersion只是文件格式版本。
   后续实验还应固定Git提交、策略参数、来源口径及每条特征真正可用的时间。
4. 同一股票、同一题材、多轮任务及相邻交易日高度相关，不能把5195条观测当成5195个独立事件。
   应按日期、股票和题材去重或聚类，按时间顺序分研究段/验证段/留出段，并避免重叠持有期泄漏。
5. 当前L2强依赖公司worker和账户。程序在线、HTTP200、keepWarm成功都不能证明研究输入完整。
   数据健康验收需覆盖实际登录、下载、首批结果、五档与价格覆盖、来源时刻及当天有效样本数。

## 优化实验建议

以下为待讨论的实验，不修改当前正式主线与明星阈值：

- 在相同候选、相同可用时点和成交假设下，对照当前规则、移除L2的基线、只用资金/广度的基线，
  检验L2到底提高了净收益/风险收益还是只减少了出手次数。数据故障期不得用于证明移除L2更好。
- 分开研究预期明星至封板、确认明星至可成交后收益、龙头候选至持仓退出，避免混成一个胜率。
- 累计大单绝对金额可能受股价、流通盘、交易时刻影响；先记录新增买入速度、成交占比、板块内相对
  强弱和持续性，做影子比较，再判断是否值得改变绝对阈值。
- 龙头评分按区间分组观察后续收益是否随分数改善，检查10/30日趋势、涨停历史、当日L2是否提供
  重复或独立信息。一次紫光等个案不能证明调整权重对全部市场有效。
- 东财与同花顺各自保持口径，不将DDE活跃度与净流入简单相加；四源主因一致也不自动等于四个
  独立信息源。基准应使用同日、同来源、同粒度的可比样本。

## 建议推进顺序

1. 恢复公司端AXTICK登录与数据返回；对重复认证失败设置可恢复的告警/退避，并让健康页明确显示
   “采集故障/不可判定”。暂不通过放宽明星阈值掩盖采集失败。
2. 建立长期只追加的研究归档与当时可用信息记录；保留故障样本和未入选候选，原始预测与盘后
   纠正分开。后续图表仍可展示历史修正，但量化成绩只用可执行时点的证据。
3. 固定两类入场实验：确认明星封板信号后是否实际可成交、龙头在明确触发条件下何时买入。
   记录排队、部分成交、未成交、延迟、复权、停牌/涨跌停、成本、仓位、退出和A股交收限制。
4. 在当前正式规则之外建立模拟交易账本，用固定资金和仓位评估净收益、回撤、盈亏比、暴露与容量，
   并同时跑简单基准。禁止把封板触达直接视为涨停价成交，也不把次日最高价默认当作卖价。
5. 数据连续可用且留出期/模拟交易结果支持后，再考虑券商接口、订单幂等、持仓对账、额度/风险
   限制及人工停机；是否实盘由Owner另行决定，不能根据当前记录承诺收益。
