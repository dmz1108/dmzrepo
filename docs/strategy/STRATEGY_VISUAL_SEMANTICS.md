# 策略页视觉语义规范(色彩与状态)

状态:**生效中**。首版 2026-07-25(Claude),源于 Owner 定稿的确认卡精修方案A;
承接并保留 Codex #262(2026-07-24)建立的"金=确认明星证据、红=人工确认主线"语义。

本文只规定**颜色与状态的对应关系**,不规定布局。任何改动策略页样式的 PR(无论哪个 agent)
都应先读本文,**避免无意翻转已建立的语义**——色彩在本项目里承载业务含义,不是纯装饰。

## 0. 为什么需要这份规范

2026-07-25 Owner 指出主线卡上"确认明星"与"预期明星"两种状态颜色看不出区别。实测:

| 状态 | 当时色值 | 色相 | 与对方 RGB 距离 |
|---|---|---|---|
| 确认明星 | `#efb94f` | 39.8° | — |
| 预期明星 | `#e7ad46` | 38.4° | **17**(< 20 人眼基本分不出) |

两者色相仅差 1.4°,等于没有区分。这类"语义不同但颜色几乎相同"的漂移,靠代码审查很难发现
(两个值分别写在相隔数千行的规则里,单看都合理),必须靠一份显式规范约束。

## 1. 状态色板(不可互换)

| 语义 | Token | 色值 | 色相 | 用在哪里 |
|---|---|---|---|---|
| **L2 确认明星**(已坐实的证据) | `--st-gold` | `#f0c04a` | 40° | 卡片边框/顶部金箔线、左柱渐变与主线分、明星条底与边、QI 金环徽章、"已确认"标签 |
| **预期明星**(未坐实,待认证) | `--st-slate` | `#7f9bbd` | 210° | 左柱、强度条、虚线明星条、灰蓝"待认证"QI 标识、"预期"标签描边 |
| **Owner 人工确认的当日主线** | `--st-red` | `#ff625d` | 2° | `.confirmed-mainline` 卡的边框/左柱/明星条 |
| **无明星**(已扫描或未达门槛) | `--st-line` / `--st-faint` | 中性灰 | — | 虚线明星条 + 扫描状态说明文字 |
| 涨(价格/资金流入) | `--st-red` | `#ff625d` | 2° | 涨幅、净流入正值 |
| 跌(价格/资金流出) | `--st-green` | `#35cf83` | 145° | 涨幅、净流入负值 |
| 交互/QI 徽标/链接 | `--st-blue` | `#4aa3ff` | 210° | 按钮、QI 主线徽标、QI 标识的绕行高亮点 |

### 硬约束

1. **确认明星与预期明星的色相必须相差 ≥ 90°**。当前 40° vs 210°(相差 170°)。新增或调整状态色时,
   先用色相角检验,不要凭肉眼在设计稿里判断。
2. **红色专属两处**:A 股涨/流入语义,以及 Owner 人工确认的当日主线。**不得**用红色表示 L2 确认明星
   ——那会让"系统判定"和"人工确认"两件事在视觉上无法区分。
3. **绿色专属跌/流出**(A 股约定,与欧美相反),不得挪作他用。
4. **冷石板 `#7f9bbd` 与交互蓝 `#4aa3ff` 色相同为 210°**,靠明度与饱和度区分(石板更暗更灰)。
   预期明星区内不要再放蓝色交互元素,避免同区内两个 210° 打架。

## 2. QI 认证标识三态

明星条左侧的 QI 标识与主页左上角 `.qi-logo` 同款(倾斜轨道 + Q/i + 绕行高亮点),用作"认证章":

| 态 | 外框 `.ml-qi-seal` | 标识 `.ml-qi-mark` |
|---|---|---|
| 确认明星 | 金环 + 径向渐变 + 外圈光晕 | 白描边 + 蓝色绕行高亮点(含原动画) |
| 预期明星 | 透明(无环) | 灰蓝、半透明、**无高亮点**(未盖章) |
| 无明星 | `visibility: hidden` | — |

**取色规则(确认/默认态)**:QI 标识必须与主页 `.qi-logo` **完全一致**——轨道 `--border-strong`、
Q/i 描边与填充 `--text`、高亮点 `--accent`。**不得**为了配合卡片主题把标识染成金色:标识是品牌资产,
"这张卡是确认态"由外框徽章环表达,不由标识本身表达。

**唯一例外(规范定义,不得删除)**:`pending`(预期明星)态——标识整体降为灰蓝半透明且**移除高亮点**,
用以表达"尚未盖章"。这是**规范批准的状态化例外**,与上面的"与主页一致"不矛盾:
一致性约束针对确认/默认态,`pending` 是显式列出的唯一变体。后续 agent **不要**以"标识颜色恒定"
为由删掉 `.ml-qi-mark.pending` 规则。除 `pending` 外不得新增任何状态化染色。

**三态外框尺寸必须一致(40×40)**,即使不可见也占位——否则三种卡片的文字起始线会错开,列表纵览时参差。

小尺寸下 viewBox 用裁切后的 `12 27 110 82`(内容包围盒),不要用主页原始的 `0 0 160 135`:
原图留白过多,34px 宽下 Q 环只剩约 12px,字形会糊成一个圆点。

## 3. 选择器特异性约定(维护陷阱)

策略页样式经多轮叠加,同一元素常有 5+ 层规则。已知需要注意的:

- 明星条相关规则必须写到 **`.ml-proof-row.ml-star-proof`** 级(特异性 0,3,1)才能接管——
  Codex #262 用的就是这一级,只写 `.ml-star-proof`(0,2,1)会被静默覆盖,且**不会报错**,
  表现为"CSS 写了但没生效"。
- `.ml-card::before` 已被左侧状态色条占用(4 处规则),卡片上新增装饰请用 `::after`。
- 卡片颜色相关的 `!important` 大量存在,新规则同样需要 `!important` 才能生效;
  这是既有技术债,不在本文范围内清理。

## 4. 改动流程

1. 改策略页颜色前先读本文;若改动会**新增或改变状态语义**,先在 `docs/strategy/discussions/`
   开讨论,由 Owner 定稿后再实现(与三要件、DDE 口径同流程)。
2. 纯视觉微调(明暗、圆角、间距)不需要讨论,但**不得改变本文第 1 节的色相归属**。
3. 改完在 `tests/strategy-workbench-ui.test.js` 补/改断言锁定色值 token,防止后续回归。
